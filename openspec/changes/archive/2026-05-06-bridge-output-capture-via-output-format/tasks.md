## 3. `runCaptureQuery` — isolated capture path

- [x] 3.1 Add `runCaptureQuery(model, captureTool, cleanedSchema, context, options, stream)` as a sibling to `startFreshQuery`. It SHALL NOT push onto `stack`, SHALL NOT mutate `cachedSessionId` / `cachedSessionCwd` / `lastSentMessageHashes` (verify by code inspection — list every read/write site of these vars in a comment in the function declaring "capture path does not touch these"). Bind a per-call logger child with `{ mode: "capture", captureTool: captureTool.name }` for log filterability. Use `_queryFactory(...)` (per task 1.4) instead of importing `query` directly so tests can inject a mock.
- [x] 3.2 Build the SDK `query()` options for the capture path:
  - `outputFormat: { type: "json_schema", schema: cleanedSchema }`.
  - No `mcpServers`. No `allowedTools` MCP filter (capture mode has no MCP surface; the SDK's synthetic `StructuredOutput` is independent of `allowedTools`).
  - `disallowedTools: DISALLOWED_BUILTIN_TOOLS` (same as agent-loop, defense-in-depth).
  - `permissionMode: "bypassPermissions"` AND `allowDangerouslySkipPermissions: true` per Decision 13 / SDK type-doc requirement (probe 0.1 confirms whether the boolean is strictly required at runtime; if not, document deviation).
  - **`cwd: os.tmpdir()`** (NOT `process.cwd()`). Capture-mode calls have no working-tree dependency; binding to the caller's cwd would leak caller state. Per Decision 12.
  - Same `extraArgs` / `settingSources: []` shape as `startFreshQuery` (factor a small `buildBaseQueryOptions(model, mode, cwd)` helper to share with `startFreshQuery` and avoid drift; `mode` parameter selects between agent-loop defaults and capture defaults).
  - **`systemPrompt: context.systemPrompt ?? ""`** verbatim (Decision 9). Do NOT call `extractSkillsBlock` / `extractAgentsAppend` / `extractAppendSystem`. Do NOT fall back to `"You are a helpful coding assistant."` — the capture caller is responsible for their own system prompt content.
  - `resume` is always omitted (capture sessions are never warm-resumed).
  - `prompt`: `buildColdStartPrompt(context.messages)` so prior turns are text-replayed (Decision 9; documented text-only/lossy fidelity limit applies to current message AND history). Empty-prompt guard: reject only when **both** `context.systemPrompt` is empty/missing AND `context.messages` produces no text via `buildColdStartPrompt` (i.e. the model has nothing to act on). When `context.systemPrompt` is non-empty but `context.messages` is empty, accept the call with `prompt: ""` (or a documented placeholder if probe 0.1 shows the SDK rejects empty `prompt`).
  - **Image-block warn-log:** before calling `buildColdStartPrompt`, walk `context.messages` and count any `{type:"image", ...}` content blocks (current message OR history). If the count is non-zero, emit a structured WARN log line `runCaptureQuery: dropping N image content block(s) — capture mode is text-only (per design Decision 9)` so a developer notices the lossy translation rather than silently producing a degraded result. Do not reject the call; the lossy path proceeds.
  - Wrap `_queryFactory({ prompt, options })` in try/catch. On synchronous throw, build `out = newTurnOutput(model)`, set `stopReason = "error"`, `errorMessage = \`capture path SDK construction failed: ${err.message}\``, push `start` + `error` events on the pi-ai stream, end the stream, and return without touching `stack` or any cache var (per Decision 12 / spec "Surface synchronous SDK construction failure as error").
- [x] 3.3 Implement `cleanSchemaForSdk(schema)` as `JSON.parse(JSON.stringify(schema))`. Add a brief code comment explaining the choice (preserves all JSON-serializable keywords at every depth; drops symbols naturally; per design Decision 6).
- [x] 3.4 Generate a `toolCall.id` of the form `toolu_<random>` for the synthesized AssistantMessage (resolved Open Question: match Anthropic's prefix to keep log infrastructure happy).
- [x] 3.5 Wire `options?.signal` to `query.interrupt()` so capture calls honor caller aborts. On abort, build an aborted AssistantMessage via `newTurnOutput(model)` with `stopReason = "aborted"` and `errorMessage = "Operation aborted by user"`, push an `error` event with `reason: "aborted"`, end the stream. In the finalize block (every termination path — success, error, abort, sync-throw), call `signal?.removeEventListener("abort", onAbort)` so long-lived `AbortController`s reused across many capture calls don't leak listeners.

## 4. Capture iterator loop and result handling

- [x] 4.1 In `runCaptureQuery`, push `start: newTurnOutput(model)` on the pi-ai stream, then iterate the SDK query's messages with a local `for await` loop (do not reuse `consumeQuery`). Capture the SDK child PID at the first `system:init` message (or earlier if exposed by the SDK) into a local `capturedPid` for later teardown verification.
- [x] 4.2 During iteration, **suppress all intermediate stream events on the pi-ai surface**. The capture path emits exactly: one `start`, then one terminal `done` or `error` (per Decision 5). This means the loop body's only job is to spot the `result` SDKMessage; all other message types (`stream_event`, `assistant`, `user`, `system`, `rate_limit_event`, etc.) are observed for logging/diagnostics only and not forwarded as pi-ai events. Document this in the function header comment.
- [x] 4.3 On `result` SDKMessage:
  - If `(message as any).structured_output !== undefined`: build `out = newTurnOutput(model)`, set `out.content = [{ type: "toolCall", id: <generated toolu_>, name: captureTool.name, arguments: structured_output }]`, set `out.stopReason = "toolUse"`, populate `out.usage` from `(message as any).usage` (mapping `input_tokens` / `output_tokens` / `cache_read_input_tokens` / `cache_creation_input_tokens` to `usage.input` / `output` / `cacheRead` / `cacheWrite`; recompute `totalTokens` and call `calculateCost(model, out.usage)`). Push `done(toolUse)` with `out`. End the pi-ai stream.
  - Else: build `out = newTurnOutput(model)`, set `out.stopReason = "error"`, `out.errorMessage = \`SDK structured-output failure: subtype=${subtype}${is_error ? " is_error=true" : ""}\``. Propagate `usage` if present and ALWAYS invoke `calculateCost(model, out.usage)` (so the `usage.cost` field is populated uniformly). Push `error` event with `out`. End the pi-ai stream.
  - In both branches, terminate the SDK query per the chosen path from probe 0.2 (default: `query.interrupt()` best-effort + break out of loop; revise to natural-close if probe 0.2 shows that's cleaner).
- [x] 4.4 If the iterator ends without ever observing a `result` message, build `out = newTurnOutput(model)`, set `stopReason = "error"`, `errorMessage = "capture path SDK iterator closed without result message"`. Push `error` event. End the pi-ai stream. (Per spec "Surface SDK iterator that closes without `result`".)

## 8. Pi-TUI scenario suite reliability (in scope — regression patch)

Folded in after independent suite re-runs surfaced pre-existing flakes in scenarios this change doesn't touch (s5, s7, s13, s20, s22-investigate). Each fix is documented per design Decision 14 and re-verified across 3 consecutive full-suite runs (18/18 PASS for the previously-flaky set).

- [x] 8.3 Pin opus for scenarios that depend on slower model execution to land their assertions deterministically:
  - `s5` (steer-mid-stream needs slow streaming so the user's Escape lands while content is generating)
  - `s13` (3-prompt rapid abort cascade needs slow turns so ≥2 onAbort events fire)
  - `s20` (bash-tool reliability — opus follows tool-use instructions more reliably than haiku, plus prompt rewrite per 8.4)
- [x] 8.4 Pin per-scenario timeout for `s22-investigate` to 300s independent of suite default, since it uses opus + extended thinking + a multi-section subagent essay (routinely 2–3 minutes).
- [x] 8.5 Rewrite s20's prompt to neutral hex sentinel `S20-SENTINEL-A4F2K` and unambiguous tool-invocation phrasing (`"Use the bash tool right now to run: … Actually invoke the tool; do not just describe it."`). The previous prompt literally contained `S20-MUST-NOT-PRINT` which both haiku and opus read as an instruction not to execute, so the test's mid-tool-execution window never opened.
- [x] 8.6 Harden s5 coherence regex. New POS uses POSIX `[^[:alpha:]]` boundaries to match clear affirmatives (`Yes.`, `Yes,`, `yes`, `Yes you`) and recall phrases (`earlier you asked`, `originally you did`); new NEG matches clear denials (`No,`, `No you`, `don't recall`, `haven't asked`, `no prior`). Validated against 12 response shapes including bare yes/no, explicit phrasings, denial phrases, and false-positive guards (`Yesterday`, `Now`, `No problem`).
- [x] 8.7 Harden s7 coherence regex. NEG was previously over-broad: `i finished` matched "I finished number 1 completely" (the model accurately reporting *which* number it completed before interruption). Tightened so NEG only fires on whole-task completion claims (`finished the count`, `completed all 100`, `reached 100`). POS expanded to robustly catch "I reached number 2" / standalone digit / "got to 2" phrasings. Validated against 12 response shapes.
